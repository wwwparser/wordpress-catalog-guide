# WordPress: блочная тема и отдельный каталог

Метод основан на разборе видео Nikita Iudin «Как я сделал сайт каталог на Фрилансе | WordPress», 12.10.2026: https://www.youtube.com/watch?v=OmzKdzCdfBA. Пример — https://cer-lab.ru/. Видео показывает готовую архитектуру, а не исходный код или пошаговую сборку. Не приписывать автору написанный агентом код. Подробности и ограничения: [references/video-method.md](references/video-method.md).

## Выбор реализации

Выясни назначение каталога, исходный макет/референс и доступную среду. Если задача — локальная проверка, создай отдельный WordPress без изменения рабочих сайтов. Для обычного каталога используй собственный CPT и категории; WooCommerce нужен при реальных заказах, корзине, оплате или складском учёте. Не добавляй эти функции по умолчанию.

## Дизайн → редактор → данные

1. Изучи макет или сайт на desktop, 990/768 и около 400 пикселей. Зафиксируй типографику, отступы, изображения, порядок секций и поведение меню. При работе по видео сначала получи расшифровку и кадры; отделяй наблюдения от догадок. Если исходного Figma-файла нет, реконструкция по кадрам не является исходным редактируемым макетом.
2. Создай дочернюю тему: `style.css` с `Template: twentytwentyfive`, `theme.json`, `templates/`, `parts/`, собственные CSS/JS. Не изменяй файлы родительской темы. Переопредели `front-page.html`, `page.html`, `single-{post_type}.html`, `404.html`, а не только `index.html`: родительский `page.html` иначе может перехватить страницы.
3. Собирай редактируемые разделы в Gutenberg/GreenShift. Для актуального синтаксиса GreenShift смотри `instruction_markdown.md` или `skills/greenlight-vibe/instructions/` установленного плагина. У Element-блоков `id == localId`, `type: inner` для контейнера и `textContent` для текста; классы и атрибуты JSON должны совпадать с сохранённым HTML. После генерации проверяй валидность в настоящем редакторе.
4. Отдельный плагин регистрирует товары, категории и поля. Используй `show_in_rest`, поддержку заголовка, редактора, миниатюры; характеристики и галерею храни в метаданных. UI сохранения проверяет capability, nonce, autosave/revision и очищает поля. Для REST-метаданных проверяй право на конкретную запись.
5. Категории могут быть самостоятельными блочными страницами с индивидуальной композицией, связанными с терминами таксономии. Не превращай их автоматически в одинаковую сетку. Общий каталог с фильтрами добавляй только по заданию: в исходном видео его сознательно отложили.
6. Повторяемые товарные сетки и карточки рендери из базы через динамические блоки. Регистрация серверного блока должна сопровождаться editor JS с `ServerSideRender` и `save: () => null`. Многострочный HTML через `core/shortcode` может получить нежелательные `<p>` и `<br>` от `wpautop`: для шапки, формы и сложной карточки предпочтителен динамический блок.
7. Карточка: хлебные крошки, галерея слева, характеристики справа; sticky-колонка только на широкой версии, на мобильной обычный поток. Запасной вывод при одной фотографии обязателен.
8. Анимации и прелоадер должны быть короткими, учитывать reduced motion и не скрывать страницу навсегда при ошибке загрузки. Используй локальные изображения и шрифты, если переносимость или проверка без внешних сервисов важны.

## Локальная проверка и перенос

Локально допускается PHP + официальный SQLite Database Integration. Базу и пароль храни вне web root и игнорируй в Git. PHP-сервер привязывай к `127.0.0.1`. На обычном хостинге используй MySQL/MariaDB или выбранную пользователем среду; перенос SQLite в MySQL — отдельная миграция, не просто копирование файла.

Перед установкой внешнего кода прочитай точки входа и подозрительные исполняемые участки. Для WordPress, темы и плагинов используй официальные источники, фиксируй версии и URL. Не копируй JS неизвестного референса и не запускай его PHP.

Проверяй настоящие страницы, карточки и категорийные ссылки; отсутствие горизонтального скролла; загрузку изображений; работу меню с клавиатуры; блоки без ошибок в Gutenberg; сохранение товара и отображение изменённого поля на фронтенде. Форму проверяй по фактической записи в базе, а не только тексту «Спасибо». Наличие нескольких фото проверяй с прокруткой sticky-колонки.

Для архива установки запусти `python scripts/package_wordpress.py <папка-темы-или-плагина> <архив-вне-исходников.zip>`. Скрипт не включает runtime, конфигурацию и базу. Архив темы требует установленной родительской темы; контент и настройки нужно переносить отдельно.

В результате передай сайт/локальный адрес, архивы, способ запуска, инструкцию редактирования и список реально проверенных функций. Если точное совпадение, Figma или публикация не выполнены, назови это явно. Изображения и контактные данные конкретного референса не становятся частью всех будущих проектов.
